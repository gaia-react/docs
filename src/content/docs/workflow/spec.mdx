`/gaia-spec` turns a feature idea into an immutable SPEC through a guided conversation, then plans it in the same session with [`/gaia-plan`](/workflow/plan/). It ends at the plan's KICKOFF prompt. It never implements anything: execution starts in a fresh session.

The SPEC is saved at `.notebook/specs/SPEC-NNN/SPEC.md`, in the gitignored notebook at your main checkout. Its plan lives inside the same folder.

## When to use it

Run `/gaia-spec` for a feature whose boundaries are not clear yet: the description has more questions than answers, or two readings of it produce different intents. It is also the way to present an idea and refine it before any code is written.

For changes whose intent is already obvious (a bug fix, a refactor against a known interface, a copy edit), just prompt Claude, or go straight to [`/gaia-plan`](/workflow/plan/).

## How to invoke

### Interactive (most common)

```
/gaia-spec your feature description
```

Claude asks you a series of questions to settle the intent. Every closed-set question is a menu with the recommended option first, plus **Discuss this** to talk it through.

### Auto mode

```
/gaia-spec auto your feature description
```

Claude answers its own questions, picking the recommended option each time, and proceeds without stopping. Use it when the description is already well-formed, or when you keep picking the recommended option anyway. A description is required: without one, auto mode aborts at once. Anything it could not settle is recorded as a deferred clarification for you to review.

## Before it starts

- **Model check.** SPEC synthesis runs on your session model. On a model other than Opus or Fable, Claude offers to stop so you can switch with `/model` first.
- **Housekeeping.** Merged and abandoned SPEC folders older than `GAIA_SPEC_RETENTION_DAYS` days (default 30) are deleted, and closed research older than its retention window is offered for removal.
- **Pull check.** When your checkout's GAIA version lags the remote, Claude offers to pull first.
- **Resume.** When an unfinished draft exists, you choose to resume it or start new. A draft another live session is still authoring is detected, so two sessions never resume the same draft.

## SPEC numbers

SPEC numbers are allocated from immutable `spec/NNN` git tags on the remote, so teammates never collide on a number, and nothing in the working tree changes to reserve one. A plan with no SPEC gets a `PLAN-NNN` number instead.

A SPEC moves through four statuses: `draft`, `ready`, `merged`, and `abandoned`.

## The flow

1. **Allocate** the SPEC number and write the first draft.
2. **Gate 1: shape.** Before any question, Claude shows the proposed intent and the proposed UATs (automated acceptance tests, in Given/When/Then form) in plain English. You confirm or revise. The confirmed shape is snapshotted so later steps can catch drift from it.
3. **Socratic loop.** One question at a time, each shaped by the last answer. A coverage scan stops the loop when every topic is settled; the ceiling is 10 substantive questions interactive and 5 in auto mode. When Claude needs facts, it runs the research itself and brings you the findings.
4. **Self-review.** A sub-agent checks the draft against the gate-1 snapshot and its own consistency. Critical and major findings come to you.
5. **Adversarial SPEC audit.** Automatically, before the final gate, independent lenses verify the draft's claims against your repository. Each finding is folded into the draft or recorded as a directive for the plan in `AUDIT.md` beside the SPEC. Because the draft is unsaved, a fix lands with no reopen ceremony.
6. **Gate 2: the artifact.** The full rendered SPEC, shown once more. Revise until it is right.
7. **Save** to `.notebook/specs/SPEC-NNN/SPEC.md`, then an immutability lint.
8. **Plan it here.** `/gaia-spec` invokes `/gaia-plan` with the SPEC in the same session. The run ends at the plan's report: a cost box and the KICKOFF prompt to paste into a fresh session.

<Aside type="caution">
Confirming gate 2 saves the SPEC and locks it. Changing a saved SPEC takes a reopen ceremony with a written rationale and a UAT diff, which the lint enforces. Settle the shape before you confirm.
</Aside>

## While a spec session runs

- **It writes only to the notebook and GAIA's local cache**: `.notebook/specs/`, `.gaia/local/cache/`, and the usage ledger. It never edits `frontend/app/**` or any other source.
- **Project decisions go into the SPEC, the wiki, or `.claude/rules/`**, never into machine-local memory.
- **Your progress is saved as you go**, after every answer and every gate, to a draft cache. Choose **Save partial and resume later** to stop, and the next `/gaia-spec` offers to resume.
- **Long sessions** reach the context checkpoint like any other: save, then continue here or clear and resume. See [Work lifecycle](/workflow/work-lifecycle/#resuming-long-work).

## After the plan runs

The plan's orchestrator renders each browser-flow UAT into a failing Playwright spec before it writes code, and closes the SPEC around the merge of its implementation. See [`/gaia-plan`](/workflow/plan/#uat-specs).

`/gaia-spec` no longer mirrors SPECs to GitHub issues, and no longer runs on spec-kit.

The run ends with a [cost box](/reference/cost/) covering the spec and the plan.
