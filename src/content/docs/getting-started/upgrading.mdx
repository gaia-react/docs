GAIA 2.0.0 moves the React app and its frontend-only Claude setup into `frontend/`, and turns the project root into a pnpm workspace that holds the shared setup. A 1.6.1 `/update-gaia` cannot make that move: its three-way merge would read every app file at its old path as deleted upstream. So a 1.6.1 project reaches 2.0.0 through a migration note bundled in the v2.0.0 release, which Claude follows in your session.

Only 1.6.1 can migrate. On an older 1.x version, update to 1.6.1 first.

## Run the migration

On the machine that does the migration:

1. Run `claude update` so Claude Code is 2.1.292 or later. The 2.0.0 audit loop that merges the migration needs it.
2. From the main checkout of your 1.6.1 project, with a clean working tree, run `/update-gaia`.
3. The 2.0.0 release notes open with a notice for 1.6.1 projects. Claude chooses **Abort** at the update question and offers to migrate instead. Choosing **Proceed** there stops with `FETCH_FAILED` and changes nothing.
4. Say yes. Only then does Claude download `gaia-bundle-v2.0.0.tar.gz`, check it against its published `.sha256`, extract it, and follow the bundled `.gaia/migrations/2.0.0.md` in the same session.

Until the note's first step, nothing else in the repository changes: no stash, commit, or branch.

If you read the release notes on GitHub instead, open Claude Code in your 1.6.1 project and ask it to migrate the project to GAIA 2.0.0.

### What the preflight refuses

The note stops with a clear message, before changing anything, when:

- `.gaia/VERSION` is not exactly `1.6.1`
- `frontend/` already exists
- the checkout is a linked worktree, not the main checkout
- the working tree has uncommitted changes (commit or discard them first, including in-flight TDD work)
- a plan has started executing (finish and merge it, or abandon it)
- Claude Code is older than 2.1.292
- `gh` is not authenticated, or `jq`, `tar`, or `shasum` is missing

Pending spec work carries over: a frozen SPEC, a plan written but not started, or an in-flight `/gaia-spec` draft.

### How it runs

- All work happens on a branch named `chore/migrate-gaia-2.0.0`. Nothing is committed on `main`.
- The note keeps a gitignored progress file, `.gaia/local/cache/shared/migrate-2/PROGRESS.md`. A new session resumes from the step it records.
- Step 7 ends in a restart: quit Claude Code and start a new session from the repository root so the 2.0.0 hooks load. The progress file picks up where it left off.
- Every commit passes your own hooks as they stand at that moment. The note never uses `--no-verify`.
- For every GAIA-shipped file, Claude three-way merges the 1.6.1 version, your version, and the 2.0.0 version: your customizations stay, GAIA's changes come in, and you are asked about any real conflict.
- It never deletes an uncommitted or untracked file of yours without asking where to keep it, never opens a `.env` file (env files are moved, not read), and never copies GAIA's lockfile (`pnpm install` regenerates it).
- It ends by opening one pull request, which merges through the 2.0.0 [Code Audit Team](/workflow/code-audit-team/).

### What moves

The note does GAIA's side of every 2.0.0 change and applies or lists the changes your own code needs. In summary:

- The app, its tests and configs, and the frontend-only rules, skills, and agents move under `frontend/`. Your `.env` files move to `frontend/`.
- Route files are renamed to `@react-router/fs-routes` flat names, and component, page, and hook folders to kebab-case, your own included. Served URLs do not change.
- Husky is replaced by native git hooks in `.githooks/`.
- spec-kit's files are removed, and GAIA's spec-lifecycle edits carry to their new paths.
- SPEC numbering moves from the committed `.gaia/specs.json` ledger to `spec/NNN` git tags, and specs, plans, and research move into the gitignored `.notebook/`.
- GAIA CI workflows, actions, and leftovers are removed.
- The Code Audit Team roster replaces the single `code-review-audit` agent, and the new [Code Audit Team](/workflow/code-audit-team/) audits the migration's own pull request.
- shadcn/ui replaces GAIA's components, stories replace component tests, and the data layer changes (see [Your own code](#your-own-code)).

### After the pull request merges

Only after the merge does Claude touch anything remote, and only on your confirmation for each act:

- push a `spec/NNN` seed tag so the next SPEC number continues from your highest one
- drop the stale `code-review-audit` required check, keeping `GAIA-Audit` and every other check
- delete the GAIA CI secrets (`CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_API_KEY`). Revoke the token at its source and uninstall the Claude GitHub App yourself; deleting the secret alone leaves the credential live.
- sync labels (renaming `severity:important` and `severity:suggestion` in place), close open `gaia-ci` pull requests, and delete `gaia-ci/` branches

It then asks before sweeping leftover local state, provisions existing worktrees that already carry the 2.0.0 layout, and hands you to `/setup-gaia`, which records the 2.0.0 setup decisions.

### Rollback

Until the pull request merges, everything is local and reversible, and nothing remote has changed:

1. Move the env files back: `mv frontend/.env* .` (only the untracked ones the note moved).
2. `git switch main`, then `git branch -D chore/migrate-gaia-2.0.0`.
3. Restore the SPEC ledger and undo the notebook move, as the note's Rollback section describes.
4. Run `pnpm install` on `main`, and confirm `git config --get core.hooksPath` prints `.husky/_`.
5. Restart Claude Code so the 1.6.1 hooks load again.

## Every other machine

The note handles the machine that runs it. Every teammate, and every other machine you use, runs these once after pulling the merged migration. Run them from the repository root of the main checkout.

1. **Activate the native git hook.** Until you do, that clone runs no pre-commit hook and reports nothing.

   ```bash
   pnpm install
   git config --get core.hooksPath
   ```

   The second command must print `.githooks`. If it does not, run `git config core.hooksPath .githooks`.

2. **Node and pnpm.** Node 22.22.0 or newer, then:

   ```bash
   corepack enable pnpm
   ```

3. **Claude Code 2.1.292 or later.**

   ```bash
   claude update
   ```

4. **Install the test browser.** `pnpm install` no longer provisions Playwright browsers.

   ```bash
   pnpm install:browsers
   ```

5. **Remove retired local state.**

   ```bash
   rm -rf .gaia/cache
   rm -f .gaia/local/harden/declines.json
   rm -rf .gaia/local/handoff
   ```

6. **Move specs, plans, and research into the notebook.** Until this runs, the spec and plan commands stop and print this line.

   ```bash
   bash .gaia/scripts/notebook/move.sh run
   ```

7. **Move the React Doctor skill under `frontend/`**, when `.claude/skills/react-doctor` exists:

   ```bash
   mkdir -p frontend/.claude/skills && mv .claude/skills/react-doctor frontend/.claude/skills/react-doctor
   ```

8. **Re-register Serena at v1.7.0**, before anyone commits an auto-migrated `.serena/project.yml`:

   ```bash
   claude mcp remove serena -s user
   claude mcp add serena -s user -- uvx --from git+https://github.com/oraios/serena@v1.7.0 serena start-mcp-server --context claude-code --project-from-cwd --open-web-dashboard false
   ```

9. **Rename abbreviated tuning variables** you export in a shell profile, CI, or `.env`. `GAIA_LEDGER_LOCK_TIMEOUT_SECS`, `GAIA_LEDGER_LOCK_STALE_SECS`, and `GAIA_LEDGER_LOCK_POLL_SECS` now end in `_SECONDS`. An old name is silently ignored.

10. **Rename an unmerged plan branch.** A branch still named `spec-<nnn>-<slug>` no longer reserves its SPEC number. Rename it with any commit type and push it:

    ```bash
    git branch -m spec-<nnn>-<slug> feat/spec-<nnn>-<slug>
    ```

11. **Run the residue sweep once.** It lists the `.gaia/local` files retired features left behind, each with the reason it is dead. Unrecognized paths are listed and never deleted.

    ```bash
    bash .gaia/scripts/state-registry-lib.sh residue-sweep
    ```

    Review the list, then run it again with `--apply` to delete exactly those files.

12. **Run `/setup-gaia`** to record this machine's 2.0.0 choices.

<Aside type="note">
GAIA no longer enables the claude-obsidian plugin, and Python 3.11 is no longer a prerequisite. The wiki stays an Obsidian vault. If you installed the plugin only for GAIA, remove it: `claude plugin uninstall claude-obsidian@agricidaniel-claude-obsidian --scope user`. That removes it from every project on the machine.
</Aside>

## Your own code

The note applies GAIA's side and lists what your own code needs. The release notes mark every such item **Action required** with the exact command. The ones most projects meet:

- **shadcn/ui role tokens.** Colors come from shadcn role tokens in `frontend/app/styles/theme.css`. Removed utilities and the `primary-*` ramp map to tokens, and GAIA's `Button`, `LinkButton`, `Toast`, form wrappers, and `react-icons` are replaced by `ui/*` components and `lucide-react`.
- **`cn`.** `cn` from the `cn` package replaces `twMerge` and `twJoin`, with `cond && 'class'` as the one conditional form.
- **`@gaia-react/lint` 3.0.0.** New rules, a required `-- reason` on every `eslint-disable`, and an opt-in `...lint.reactRouter` group. `frontend/eslint.config.mjs` is yours, so a few spreads are added by hand.
- **Stories as tests.** React Testing Library, happy-dom, and jsdom are gone. Convert component tests to stories with play functions and hook tests to `vitest-browser-react`.
- **Chromatic modes.** Replace `chromatic: {viewports: [...]}` with mode viewports, and `excludeDark` with `modes: {dark: {disable: true}}`.
- **msw 3.** Migrate your handlers with `npx codemod@latest run @mswjs/v3`.
- **Data layer.** Services are Ky and Zod modules, and `create()` defaults to camelCase. A snake_case backend passes `{isSnakeCaseEnabled: true}`.
- **`FormError`'s `hide` prop** is now `isHidden`.
- **Label renames.** `priority:high`, `priority:critical`, and `needs-human-review` in your own workflows or templates become `severity:major`, `severity:critical`, and `needs-human`.
- **React Compiler** is on by default. Run `pnpm lint` and your full suites; to roll back, set `isReactCompilerEnabled = false` in `frontend/react-compiler.config.ts`.

Commands you knew in 1.x have new names or are gone. See [What changed in the commands](#what-changed-in-the-commands).

## What changed in the commands

| 1.x | 2.0.0 |
|---|---|
| `/gaia-audit` | [`/gaia-cleanse`](/maintenance/cleanse/), narrowed to memory and auto-loaded files |
| `/gaia-harden` | [`/gaia-codify`](/maintenance/codify/) |
| `/setup-gaia-ci`, `/setup-cloned-gaia-project` | [`/setup-gaia`](/getting-started/setup-gaia/) |
| `/gaia-handoff`, `/gaia-pickup` | Removed. Resume from the run folder's `STATE.md` or a continuation prompt. See [Work lifecycle](/workflow/work-lifecycle/#resuming-long-work). |
| `/gaia-debt list`, `why`, `fix` | Removed. `/gaia-debt` takes no argument or issue numbers. |
| `/gaia-wiki sync`, `consolidate`, `lint`, `--force` | `/gaia-wiki` takes no arguments and always runs all three. |
| `/speckit.gaia.*` | Removed with spec-kit. |
| GAIA CI | Removed. Audits run locally. |
| `code-review-audit` agent | The [Code Audit Team](/workflow/code-audit-team/) |

There are no aliases. User-only commands (`/gaia-init`, `/setup-gaia`, `/gaia-fitness`, `/gaia-forensics`, `/gaia-codify`, `/gaia-residue`, `/gaia-serena-sync`) no longer appear in Claude's skill listing and Claude never starts them on its own. Type them as slash commands.
