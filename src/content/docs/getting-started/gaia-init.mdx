`/gaia-init` runs automatically during `npx create-gaia`. It renames the project to your title, sets up language support and how routes load data, removes GAIA's own branding, sets up CODEOWNERS and your environment file, registers Claude tools and plugins, verifies the build, and commits the result. You get a project that compiles, lints, and tests cleanly.

`/gaia-init` runs only at the root of a project created by `npx create-gaia`, and refuses anywhere else. You start it by typing it; Claude never starts it on its own.

## The flow

### 1. Dependencies

1. Ensures [pnpm](https://pnpm.io/) is available and new enough. GAIA requires pnpm 12 or later (the version pinned in `package.json` `packageManager`). If pnpm is missing, init enables it with `corepack enable pnpm`, or installs it globally with npm when Corepack isn't available. If an older major version is on your `PATH` (for example 11.x), init asks you to confirm the upgrade first. It stops if an older pnpm still comes first on your `PATH` after the upgrade.
2. Runs `pnpm install` in the new project.
3. Runs [`/update-deps`](/maintenance/update-deps/) to bring every package to its latest compatible version and resolve every security advisory it can. In this mode it asks no questions, undoes any fix that fails the quality gate, and commits nothing; init's own commit at the end includes the changes. Anything it holds back is listed with a reason.

If install fails, the run stops and shows the error. Fix the cause and resume (see [Resuming after a failure](#resuming-after-a-failure)).

### 2. Questions about your project

Before it asks about your project, `/gaia-init` asks how you want to answer the setup questions:

- **Interactive** (recommended): GAIA asks each question and waits for your answer.
- **Automatic**: GAIA picks the recommended default for every question. It shows you the full list of chosen values and then carries on without stopping. You can interrupt it, and you can change any setting afterward.

Every question is a menu with the recommended option first. In interactive mode it asks:

- **Primary language.** The main language for your app's UI. The first option is the language you have been typing in. The second is always a different real language: English when you type in another language, otherwise your system locale's language, or Spanish. Type any other language, by name or code, through the menu's Other answer.
- **Additional languages.** Keep only the primary language with translation support (i18n) still set up (recommended, so you can add languages later with no rework), add more languages now, or remove i18n entirely. Removing it is hard to undo, so pick it only if you are sure the app will only ever use one language.
- **GitHub username for CODEOWNERS.** GAIA reads your handle from the [GitHub CLI](https://cli.github.com/) you are logged in to (`gh api user`) and offers it first. Choose **Set it later** to write a placeholder you edit before pushing, or type a different handle. If detection fails, GAIA asks you to type your handle rather than guessing.
- **Project title.** Your folder name in title case (for example `my-cool-app` becomes `My Cool App`), or the folder name as it is. Type your own title through Other. The slug (the kebab-case name used in package names and paths) comes from the title, so it is never asked separately. To set both, type `Title / slug`.
- **Backend field casing.** How your backend names JSON fields. `camelCase` (recommended) passes keys through unchanged. `snake_case` makes the services convert keys: `snake_case` in requests and responses, camelCase in your code (`create({isSnakeCaseEnabled: true})`). **Not sure** is treated as camelCase.
- **[TanStack Query](https://tanstack.com/query/latest).** Off by default: route loaders handle data and nothing extra is installed. **Yes** installs a pinned TanStack Query and sets up its provider and [Storybook](https://storybook.js.org/) decorator.

Both data answers (casing and TanStack Query) can change later with `./.gaia/cli/gaia init configure-data-layer --casing snake` or `--query true`.

The language, title, and identity questions are re-asked until you answer; GAIA never guesses them. The two data questions are asked again once, then fall back to their default.

<Aside type="caution">
Removing i18n is hard to undo. Choose it only if you are certain the app will only ever use one language. Keeping it set up lets you add languages later with no rework.
</Aside>

### 3. Branding, naming, data layer, and i18n

With your answers, `/gaia-init`:

- removes GAIA's branding: it writes a new `README.md` for your project and puts your title on the Storybook sidebar
- sets up i18n for the languages you chose, and creates starter files for each non-English one
- sets up route data loading for your casing and TanStack Query answers
- renames the project to your title and slug
- adds the statusline to the project's `.claude/settings.json`

If you removed i18n, it removes all of it cleanly.

### 4. Project files and build check

- Creates `.github/CODEOWNERS` with your GitHub handle as the repo-wide owner. When it has no real handle, it writes the placeholder `REPLACE-WITH-YOUR-GITHUB-HANDLE` and tells you to edit it before you push. GitHub also warns about the unknown owner, so you won't miss it.
- Copies `frontend/.env.example` to `frontend/.env` if you do not already have one. The app's environment file lives in the `frontend/` package; [Playwright](https://playwright.dev/) reads the same file.
- Runs the full quality gate from the repository root, `pnpm typecheck && pnpm lint && pnpm test:ci && pnpm build` (the root scripts run the `frontend` package), and stops if anything fails. This step is what makes sure the project compiles, lints, and tests cleanly, and it is the main reason init takes a few minutes.

### 5. Claude tooling

`/gaia-init` sets up the outside tools and plugins GAIA uses. GAIA's skills and rules already ship with the project. You don't run any of this by hand; it is listed for reference. [`/setup-gaia`](/getting-started/setup-gaia/) runs the same steps on every other machine.

**Tools.** Installed on each machine, not tracked in the repo:

- [React Doctor](https://github.com/millionco/react-doctor): `bash .gaia/scripts/install-react-doctor.sh` installs the `react-doctor` skill under `frontend/.claude/skills/`, so it only loads in sessions that work on the app.
- [Playwright CLI](https://github.com/microsoft/playwright-cli) binary: `npm install -g @playwright/cli@latest`. The `playwright-cli` skill that ships with GAIA uses it, and [`/update-deps`](/maintenance/update-deps/) reports when it falls behind.
- [Serena](https://github.com/oraios/serena) MCP server, registered globally for your Claude Code:

  ```bash
  claude mcp add serena -s user -- uvx --from git+https://github.com/oraios/serena@v1.7.0 serena start-mcp-server --context claude-code --project-from-cwd --open-web-dashboard false
  ```

  Serena needs `uv`, Astral's tool for running Python programs. If `uv` is missing, `/gaia-init` installs it first with `curl -LsSf https://astral.sh/uv/install.sh | sh`.

  Claude prefers Serena's code tools over its built-in Read, Grep, and Edit only when Claude Code starts with Serena's extra system prompt. The recommended way to start a session is:

  ```bash
  claude --append-system-prompt="$(serena prompts print-cc-system-prompt-override)"
  ```

  A plain `claude` still works; in that case the `serena-cc-override` rule that ships with GAIA tells Claude to prefer Serena.

**Plugins.**

```bash
claude plugin install typescript-lsp@claude-plugins-official
```

After installing, `/gaia-init` checks each one and reports `[ok]` or `[FAIL]` for each. A failure stops the run so you can retry before continuing.

### 6. Team settings

`/gaia-init` applies GAIA's two team defaults without asking:

- **Git isolation policy**: always use worktrees. Init leaves the setting out of `.gaia/project.json`, because an unset policy means this default. Every `/gaia-plan`, `/gaia-debt`, and ad-hoc task works in its own git worktree, so tasks run in parallel without touching each other. See [Work lifecycle](/workflow/work-lifecycle/).
- **Sandbox recommendation**: not recommended, written to `.gaia/project.json`. Claude Code's operating-system sandbox for shell commands breaks `gh`, git over HTTPS, and `docker` until you allow each one, and GAIA's whole workflow depends on `gh`.

The file is committed and shared with your team, and `/update-gaia` never overwrites it. A repo admin changes either setting later with `/setup-gaia --reconfigure`.

### 7. Wiki reset

GAIA ships with a built-in [wiki](/maintenance/wiki/) that Claude maintains as it works. Init replaces its log, `wiki/log.md`, with a single entry for your project so it starts with its own context instead of GAIA's development history.

### 8. Commit

`/gaia-init` commits its own changes as one commit on the current branch, `chore: initialize project with /gaia-init`. [`/setup-gaia`](/getting-started/setup-gaia/) pushes only what is committed, and every later branch or worktree starts from the last commit. Committing makes sure nothing init wrote is left behind. If the commit fails, init says so and tells you to review `git status` and commit before running `/setup-gaia`.

## Usage ping

`/gaia-init`, `/setup-gaia`, `/update-gaia`, and the 2.0.0 migration each send one request to `telemetry.gaiareact.com` and don't wait for a reply. It carries a few fields with fixed choices for that event (for `/gaia-init`, the run mode and the number of languages), a pseudonymous ID for this install (`projectId`), the GAIA version, and a broad platform (`macos`, `linux`, `windows`, or `other`). It never carries paths or free text. It never blocks or fails the command, and a network failure is ignored.

To turn it off, set the variable in your shell profile:

```bash
export GAIA_TELEMETRY_PING_DISABLE=1
```

## After gaia-init completes

Init marks this machine's setup as done and deletes its own one-time setup files. Then it prints:

```
<Project Title> is ready for development. Exit Claude, then from your terminal:

cd <project-folder-name>

Then start Claude again, and run /setup-gaia. After your first push, /setup-gaia registers the GAIA-Audit required check.
```

If `.github/CODEOWNERS` still holds the placeholder owner, a required follow-up to edit it comes first.

Exit Claude and relaunch from inside the project folder. New plugins and skills only load in a new session.

<Aside type="caution">
When you exit Claude, your shell returns to the directory you launched from, not the project folder. Run `cd <project-folder-name>` before relaunching, or the new plugins and skills will not load.
</Aside>

From there you are ready to build. Run `pnpm dev` to start the app locally, or ask Claude to run it. When you are ready for GitHub, run [`/setup-gaia`](/getting-started/setup-gaia/); it creates the GitHub repo for you (or uses one you already created). [Onboarding, as you build](/getting-started/onboarding/) shows what GAIA does as your first commits and pull requests land.

## Resuming after a failure

`/gaia-init` records its progress in `.gaia/init-state.json`. If something breaks partway through, the failing step prints an error saying what went wrong. Fix the cause and run:

```bash
.gaia/cli/gaia init resume
```

Steps that already finished are skipped, and the rest run again with the answers you already gave.
