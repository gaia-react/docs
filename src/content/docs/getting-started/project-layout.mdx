A GAIA project is a pnpm workspace: one repo holding more than one package. The root holds the Claude setup and tooling shared by the whole repo. The React app, and the Claude setup that applies only to it, live in the `frontend/` package.

## The root

| Path | What it holds |
|---|---|
| `CLAUDE.md` | Project instructions Claude reads at every session start |
| `.claude/` | Shared commands, skills, agents, hooks, rules, and settings |
| `.gaia/` | GAIA's CLI (`.gaia/cli/gaia`), scripts, statusline, the Code Audit Team roster (`audit-ci.yml`), team settings (`project.json`), the label registry, and state kept only on your machine under `.gaia/local/` (gitignored) |
| `.githooks/` | Git's own hooks: `pre-commit` and `commit-msg` |
| `.github/` | The Tests, Chromatic, and PR Conventions workflows, and your `CODEOWNERS` |
| `wiki/` | The project wiki Claude maintains, an Obsidian vault |
| `.notebook/` | Specs, plans, and research (gitignored, in your main copy of the repo, not in worktrees) |
| `package.json`, `pnpm-workspace.yaml`, `pnpm-lock.yaml` | The workspace: one lockfile for the whole repo, the dependencies GAIA's own tooling needs, and pnpm's settings that protect against compromised packages |

The scripts at the root (`pnpm dev`, `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm pw`, `pnpm build`) run in the `frontend` package, so `pnpm lint` and `pnpm -C frontend lint` do the same thing.

## frontend/

| Path | What it holds |
|---|---|
| `frontend/CLAUDE.md` | Instructions for sessions working on the app |
| `frontend/.claude/` | The app's skills, rules, and Code Audit Team extensions. Its `settings.json` is generated from the root settings plus `settings.overlay.json`. |
| `frontend/app/` | The React Router app: `routes/`, `pages/`, `components/` (with shadcn/ui in `components/ui/`), `hooks/`, `services/`, `state/`, `languages/`, `styles/` |
| `frontend/test/` | Test setup, mocks, and utilities |
| `frontend/.storybook/` | Storybook config, including the accessibility settings in `a11y.ts` |
| `frontend/.playwright/` | Playwright specs and helpers |
| `frontend/.env` | Your environment file (gitignored). `frontend/.env.example` is the template. |
| `frontend/package.json` | App dependencies |

Files and folders under `app/components`, `app/pages`, and `app/hooks` are kebab-case: a component is `components/<name>/index.tsx`, a page is `pages/<route path>/page.tsx`, and a hook is `use-<name>.ts`. Each folder keeps its tests and stories in a `tests/` folder beside the code.

Each copy of the repo, your main one and each worktree, gets its own dev, Storybook, and Playwright ports, so they never collide. The main copy uses 5173 and 6006. To see a copy's ports, run `bash .gaia/scripts/ports.sh` in it.

To add another package beside `frontend/`, such as a backend, ask Claude. GAIA ships step-by-step instructions for it. Before it runs backend work in a worktree, Claude asks whether every worktree should share one backend or run its own.

## The frontend stack

- **React and React Router.** Routes come from file names through React Router's `@react-router/fs-routes`. Files sit in one flat folder, with dots separating the URL segments (`_public.tsx`, `_session.dashboard.tsx`).
- **React Compiler**, on by default in the build, dev server, Vitest, and Storybook. It is configured in `frontend/react-compiler.config.ts`; set `isReactCompilerEnabled = false` there to turn it off.
- **shadcn/ui** for components, built on Base UI, with `class-variance-authority` for variants and `lucide-react` for icons. Add components with `pnpm shadcn add <name>`. Forms are built from the `ui` controls with Conform.
- **Tailwind v4 with role tokens.** Every color is a named role (for example primary or muted), defined once as a shadcn token in `frontend/app/styles/theme.css`. Change your theme by editing those values. `cn` from the `cn` package combines class names.
- **One way to load route data.** Services use Ky for requests and Zod to check every response, and the same code runs on the server and in the browser. A route reads its data on the server, in the browser, or through TanStack Query (off by default). `create()` leaves keys in camelCase; if your backend uses snake_case, turn on conversion with `create({isSnakeCaseEnabled: true})`.
- **Stories as tests.** Components are tested through Storybook stories with play functions (scripted interactions), run in a real Chromium browser under Vitest. Every story is checked for accessibility. Hook tests use `vitest-browser-react`. HTTP is mocked with MSW 3. Chromatic takes a screenshot of each story in a light and a dark mode.
- **Translations (i18n)** with react-i18next, unless you removed them at init.
- **`@gaia-react/lint`** for ESLint, Stylelint, and commitlint. Prettier formats code, and Knip finds unused code.
- **Toolchain:** Node 22.22.0 or newer, pnpm 12 (pinned in `packageManager`), and Vitest 5.

The paths the app submits fetchers to are defined once in `frontend/app/action-paths.ts`, so renaming a route fails a test instead of returning a 404 at runtime. `hydration.spec.ts` is the Playwright example of checking that a page loads with no `console.error` or page errors.

A new project starts plain and unbranded: neutral gray-scale shadcn color tokens, system fonts, and a simple layout. The `design-baseline` rule treats that styling as a placeholder until you settle on your own design.

For the reasoning behind each choice, ask Claude: the decisions live in the project wiki.
