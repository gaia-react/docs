Everything in GAIA is installed from the start: every rule, hook, check, and command is there in your first session. You don't switch anything on. Each part kicks in when your work reaches it, so a new project meets them in a predictable order.

## First session

- **Rules load.** Some rules are always loaded and shape what Claude writes from the first prompt. Others apply to certain folders or file types and load only when the work touches those files. See [Rules](/reference/rules/).
- **Skills trigger from plain prompts.** Ask for a component and `new-component` scaffolds it; edit a hook and `react-code` applies. See [Skills](/skills/).
- **Guards are on.** Hooks block reading secrets, dangerous deletes, and commits to `main`, whether or not you skip permission prompts. See [Hooks](/reference/hooks/).
- **The statusline** shows `⚙️ /setup-gaia` until this machine's setup is done.

## First commit

- **Its own branch and folder.** If the work closes an issue, Claude claims it first ([why](/reference/gates/#issue-claim)). Then it names the branch and works in its own git worktree, a separate copy of the repo on that branch ([why](/reference/gates/#worktree-path-mismatch)). See [Work lifecycle](/workflow/work-lifecycle/).
- **Quality Gate.** Before Claude commits, typecheck, lint, tests, Playwright, a quick check that the dev server starts, and the build must all pass ([why](/reference/gates/#quality-gate)).
- **Test seen failing first.** A new test for plain logic (utilities, parsers, hooks) must be seen failing before it passes, which proves it can catch a bug ([why](/reference/gates/#test-seen-failing-first-red-gate)).
- **Commit hooks.** The native pre-commit hook runs typecheck, lint, and tests on staged files ([why](/reference/gates/#pre-commit-floor)), and the commit-msg hook checks the message follows Conventional Commits ([why](/reference/gates/#commit-message-format)). Neither can be skipped ([why](/reference/gates/#no-verify)).

## First pull request

- **Draft and title.** The pull request opens as a draft ([why](/reference/gates/#draft-pull-requests)) with a title that passes the same lint as a commit message, since a squash merge uses the title as the commit message ([why](/reference/gates/#pull-request-title)).
- **Code Audit Team.** A set of AI reviewers, each responsible for certain files. Every reviewer whose files the change touches reviews it before it can merge ([why](/reference/gates/#merge-without-the-audit)). See [Code Audit Team](/workflow/code-audit-team/).
- **The audit loop.** Rounds of review, fix, and re-check run in a separate agent, outside your session, until the change passes the audit.
- **The branch checkpoint.** When your session's context reaches GAIA's [red band](/workflow/work-lifecycle/#resuming-long-work), or the rounds keep turning up new problems instead of settling, the loop stops and asks you whether to continue ([why](/reference/gates/#audit-checkpoint)).
- **GAIA-Audit.** Once the audit passes, Claude posts a `GAIA-Audit` status check on the pull request. Once a repo admin has run [`/setup-gaia`](/getting-started/setup-gaia/), GitHub requires it before merging ([why](/reference/gates/#gaia-audit-required-check)).
- **Merge**, when you ask. The merge prints the pull request's [cost](/reference/cost/), posts the findings comment, and releases the issue claim.

## First week

- **Tech-debt issues appear.** When the audit finds a problem in code the change didn't touch, it files a `tech-debt` issue instead of fixing it there. Security findings are not filed publicly. See [How issues are filed](/maintenance/debt/#how-issues-are-filed).
- **Maintenance nudges.** The statusline starts naming commands when they are due: `🐛 /gaia-debt` once tech-debt issues are open, `📦 /update-deps` when packages are outdated or have open security advisories, `🚀 /update-gaia` when a release is out, `🧠 /gaia-wiki` once the wiki falls 20 commits behind the code, and `🔎 /gaia-cleanse` once memory grows or a month passes. See [Maintenance](/maintenance/).

## Later

- **[`/gaia-debt`](/maintenance/debt/)** fixes the backlog, highest severity first, through the same audit.
- **[`/gaia-residue`](/maintenance/residue/)** appears once 5 or more trade-offs that reviewers accepted at merge are at least 30 days old.
- **[`/gaia-codify`](/maintenance/codify/)** appears once the audit has made the same kind of finding on 3 or more pull requests within 90 days, and proposes a check that stops it from happening again.

Every check above, and every other one, is in the [gate reference](/reference/gates/) with what it stops, why, when it fires, and how to clear it.
