GAIA's GitHub labels are all defined in one file, `.gaia/labels.json`. `gaia labels sync` creates the labels your repository is missing and renames labels whose names changed, so every issue keeps its label. When a label's color differs from GAIA's, it tells you instead of overwriting your color.

[`/setup-gaia`](/getting-started/setup-gaia/) and [`/update-gaia`](/maintenance/update-gaia/) run the sync. You can also run it yourself:

```bash
.gaia/cli/gaia labels sync
```

Add `--dry-run` to see what it would change, or `--adopt` to replace your colors with GAIA's. If your GitHub token is not allowed to edit labels, it prints the `gh label` commands for you to run yourself.

## Tech debt

| Label | Meaning |
|---|---|
| `tech-debt` | A review finding outside the pull request's scope, saved to be fixed later by [`/gaia-debt`](/maintenance/debt/) |
| `severity:critical` | Wrong, or will produce broken work; fixed first |
| `severity:major` | A significant gap or defect; fixed before minor findings |
| `severity:minor` | Real but small; fixed by default, never skipped |
| `severity:investigate` | Severity not known yet; needs research before it can be graded |
| `difficulty:easy` | The issue text and the code it points to make the fix clear |
| `difficulty:medium` | The fix needs a design decision, and the surrounding code shows which way to go |
| `difficulty:hard` | The fix needs a design decision the surrounding code does not answer |
| `footprint:narrow` | One piece of code in one file, with no change to how other code calls it |
| `footprint:wide` | Touches several files, changes how other code calls it, or changes the structure |
| `footprint:spec` | Needs a design SPEC first; fixed through `/gaia-spec` |
| `debt:spec-pending` | Handed to `/gaia-spec`; on hold until the SPEC starts |
| `debt:spec-active` | A SPEC is in progress for this issue, or is keeping it open until a recorded condition is met |

The severity labels are shades of red, darkest for critical.

## Work in progress

| Label | Meaning |
|---|---|
| `in-progress` | Someone is working on this issue right now; do not pick it up. Added when the issue is [claimed](/workflow/work-lifecycle/#1-claim) and removed when the pull request that closes it merges. |
| `needs-human` | An automated process stopped here; a person needs to review it. |

## Issue types

| Label | Meaning |
|---|---|
| `bug` | Existing behavior is broken or wrong |
| `enhancement` | A new feature or request |
| `documentation` | Improvements or additions to documentation |
| `security` | A security defect or dependency CVE |
| `wontfix` | Deliberately declined; do not file it again. When a finding matches an issue with this label, it is not filed as tech debt again. |
| `dependencies`, `github_actions` | Dependabot's own labels |

## Not created

GitHub's default `good first issue` and `help wanted` labels are deliberately absent from GAIA's registry: they invite one-off contributions from people who do not know the background of the work.

## Renamed in 2.0.0

`gaia labels sync` renames these, and every issue keeps its label:

| 1.x | 2.0.0 |
|---|---|
| `severity:important` | `severity:major` |
| `severity:suggestion` | `severity:minor` |
| `priority:high` | `severity:major` |
| `priority:critical` | `severity:critical` |
| `needs-human-review` | `needs-human` |

Update the old names in your own workflows or templates by hand; find them with `git grep -n -E 'priority:(high|critical)|needs-human-review'`. The 1.x `gaia-ci` label is deprecated; `gaia labels sync --prune-deprecated` removes it.
