GAIA ships seven sub-agents in `.claude/agents/`. None is invoked directly: each is dispatched by a workflow at the point it needs one. Each pins a model and runs at `medium` effort whatever your session's `/effort`, unless `CLAUDE_CODE_EFFORT_LEVEL` is set; the pinned effort needs Claude Code 2.1.292 or later.

| Agent | Model | Dispatched by | Edits files? |
|---|---|---|---|
| [`code-audit-frontend`](#code-audit-frontend) | Opus | the audit loop | No |
| [`code-audit-github-workflows`](#code-audit-github-workflows) | Opus | the audit loop | No |
| [`audit-loop-unit`](#audit-loop-unit) | Opus | the merge workflow | Commits fix rounds |
| [`audit-light-reviewer`](#audit-light-reviewer) | Sonnet | the audit loop, on a light route | No (read-only) |
| [`worthiness-evaluator`](#worthiness-evaluator) | Opus | the `tdd` skill | No |
| [`uat-fidelity-judge`](#uat-fidelity-judge) | Opus | a SPEC plan's orchestrator | Writes its verdict file only |
| [`fitness-judge`](#fitness-judge) | Sonnet | `/gaia-fitness` | No (read-only) |

## The Code Audit Team

The pre-merge audit is a team: each member owns the files its globs claim in `.gaia/audit-ci.yml`, and a pull request is reviewed by every member whose files it touches. Members only report; a separate fixer repairs, and a deterministic verifier checks each repair. Every finding is graded Critical, Major, or Minor. See [Code Audit Team](/workflow/code-audit-team/) for the roster, clearances, and the loop.

### code-audit-frontend

The default member. Owns the app and its tooling: `frontend/app/**`, tests, Storybook and Playwright trees, manifests, build and lint configs, root tooling such as `.npmrc`, and `frontend/.claude/**`. It reviews what lint and types cannot: security (a critical priority), performance, architectural fit, robustness and edge cases, accessibility, and maintainability. It also flags quadratic lookups split across a component or function boundary.

Three specialist sub-agents review React patterns and accessibility, TypeScript and architecture, and translations. Library-specific rules load from `frontend/.claude/agents/code-audit-frontend/`: `cn`, Conform, the form components, React buckets, react-i18next, and shadcn. React Doctor, Knip, and dependency advisories feed it too, as advisory input.

Every Critical or Major finding of its own is handed to a fresh-context refuter before it is reported, so a finding that cannot survive an independent check is dropped or demoted. Each reply ends with a `Files reviewed` count, so an early stop is caught rather than read as clean.

### code-audit-github-workflows

Owns `.github/workflows/*.yml` and `.github/actions/**/*.yml`. Reviews workflow YAML for script injection, unsafe `pull_request_target` use, unpinned third-party actions, over-broad permissions, and secret handling.

### audit-loop-unit

Runs a window of audit rounds off your main session: dispatches the members, the fixer, and the verifier, runs the Quality Gate, commits and pushes each round's fixes, and returns a thin report. Your session holds only that report, so a long audit does not fill its context. It never merges and never posts `GAIA-Audit`; the main session does both. It is the one agent allowed to dispatch agents of its own, which needs Claude Code 2.1.292 or later.

### audit-light-reviewer

Reviews a small change since a member's last full review, when the member opted in with `light_review: true`. Read-only. Whenever the light route cannot be established, the full member runs instead.

## Tests and acceptance

### worthiness-evaluator

An advisory reviewer for tests on the emergent surface (stories and Playwright), where the failing-first RED gate does not apply. The `tdd` skill dispatches it after tests go green. It reads only the tests the work changed plus their sibling suites, and edits nothing.

Each test is judged on two axes:

- **Honesty**: can the test fail for a real reason? It must assert through the public interface (roles, accessible names, visible text), not implementation detail, and survive an internal refactor.
- **Worthiness**: is it worth keeping? It should exercise your own code rather than a dependency, and a composition test should not re-prove what a child's suite already covers.

One verdict per test: `keep`, `fix`, or `delete`. A `fix` names the defect; a `delete` is always a proposal you confirm, with its evidence. A merge hook checks that every changed test of this kind has a verdict for its current content.

### uat-fidelity-judge

Before a SPEC plan's pull request is audited, reads the SPEC and each rendered Playwright UAT spec and judges whether each test body still asserts its contract. Writes one JSON verdict file. A failure halts the plan.

## Integration health

### fitness-judge

The advisory judgment pass of [`/gaia-fitness`](/maintenance/fitness/): description substance, trigger overlap between skills, rule scope against `paths:` globs, and terminology within a skill. Read-only, and it never moves the grade.

## Retired

The single `code-review-audit` agent of 1.x is replaced by the Code Audit Team. Its `GAIA-Audit:` commit trailer is retired; the `GAIA-Audit` status check is unchanged and still required.
