Hooks are scripts Claude Code runs on events: before or after a tool call, when a session starts or stops, when you submit a prompt. GAIA registers them in `.claude/settings.json`; the app's `frontend/.claude/settings.json` is generated from the root settings plus an overlay, so the same hooks run in either. The scripts live in `.claude/hooks/`.

Unlike [rules](/reference/rules/), hooks are deterministic. A guard hook denies a tool call whatever the model decided, and its denial message names the allowed spelling or the next step. Running Claude Code with `--dangerously-skip-permissions` skips permission prompts, not hooks.

Advisory hooks carry an `if` filter so a typical Bash call starts only the hooks that apply to it. Guard hooks never carry one. Every registration resolves from the repository root, so a `cd` in a Bash call cannot leave a hook unfindable, and a blocking hook refuses when `jq` is missing instead of allowing the call.

Why each guard exists, and how to clear it, is in the [gate reference](/reference/gates/).

## Guards (can deny a tool call)

### Bash and Monitor commands

| Hook | Denies |
|---|---|
| `block-main-destructive-git` | Commits on `main` or `master`, force-pushes naming them, any push from them or with a `main`/`master`/`HEAD` source refspec, and a `git checkout` or `git switch` that would move the main checkout off another session's open-PR branch. |
| `block-no-verify` | `git commit` or `git push` with `--no-verify`, `-n` on a commit, or `-c core.hooksPath=<path>`. |
| `block-rm-rf` | `rm -rf` of `/`, an absolute path outside the scratch whitelist, `$HOME`, `.`, `*`, dotfile globs, `.git`, `.claude` and its children, and `node_modules`, plus `--no-preserve-root`. Scratch paths and the session scratchpad are allowed. |
| `block-sensitive-read` | Reading dotenv files (`.env` and every `.env.<name>` except `.env.example`), keys (`.key`, `.pem`), credential files, and anything under a `secrets` directory, through Bash readers, `source`, redirects, and filter flags such as `rg -g '*.key'`; and bare `env` or `printenv` dumps. Also registered on Read and Grep. |
| `block-manifest-write` | Writes to `.gaia/manifest.json`, which lists only the files GAIA ships. `/update-gaia` writes it through a marked exemption. |
| `block-invalid-pr-title` | A `gh pr create` or `gh pr edit` whose title would fail the PR Conventions lint as a squash subject (the title plus ` (#<n>)`), and `--fill` with no `--title`. |
| `block-pr-create-without-draft` | A `gh pr create` for this repository without `--draft`. |
| `block-fork-pr-checkout` | `gh pr checkout` or a `git fetch` of `pull/<n>/head` for a pull request from a fork, or one `gh` cannot classify. |
| `block-handrolled-pr-poll` | A shell loop polling `gh pr view` or `gh pr checks` without reading `mergeable`; use `bash .gaia/scripts/pr-wait-merge.sh --pr <N>`. |
| `pr-merge-audit-check` | `gh pr merge` until every Code Audit Team member the diff dispatches has cleared it. Posts the `skipped:` status itself for an out-of-scope or manifest-only `chore(deps)` pull request. |
| `worthiness-presence-check` | `gh pr merge` when a changed story or Playwright test has no worthiness verdict for its current content. |
| `red-verify-commit-check` | `git commit` of a new, passing test on the deterministic surface that was never seen failing. |
| `block-audit-loop-write` | Writes to the audit loop's protected state and context readings, and running the grant recorders by hand. |

### Edit, Write, and MultiEdit

| Hook | Denies or asks |
|---|---|
| `block-secrets-write` | Content holding an AWS key, a GitHub token, a private key header, or a secret-named assignment with a real-looking value (including `export`, `declare`, and `local` forms), and any write to a `.env` file except `.env.example`. |
| `block-eslint-config-edit` | **Asks** you to confirm any edit to an `eslint.config.*` file, and explains why: a config edit can silence a rule as easily as it can make a sanctioned migration. |
| `block-manifest-write` | Writes to `.gaia/manifest.json`. |
| `block-worktree-path-mismatch` | An edit whose path resolves into a different checkout than the worktree the session works in. Writes to the main checkout's `.notebook/` are exempt. |
| `block-audit-loop-write` | Writes to the audit loop's protected state. |

### Agent and Task dispatches

| Hook | Bounds |
|---|---|
| `audit-loop-bound` | Each dispatch of the audit loop unit and of a Code Audit Team member, per branch: the context checkpoint, the convergence signals, and the hard round cap. Denies at a checkpoint until a human answers. |

## Recorders and context

| Hook | Event | What it does |
|---|---|---|
| `audit-loop-grant` | UserPromptSubmit | Records `audit-grant <n>` or `audit-accept`, typed as the whole prompt in an interactive session. |
| `audit-loop-ask-grant` | PostToolUse (AskUserQuestion) | Records a selection of the audit checkpoint's pinned question. |
| `post-findings-block-on-merge` | PreToolUse (`gh pr merge`) | Posts the pull request's consolidated findings comment, the input `/gaia-codify` tallies. Never blocks. |
| `capture-red-observations` | PostToolUse and PostToolUseFailure (Bash) | Records failing test runs, so the RED gate can see a test failed before it passed. |
| `capture-gh-artifact` | PostToolUse (`gh pr create`) | Links the pull request to its branch in the usage ledger. |
| `pr-merge-cost` | PostToolUse (`gh pr merge`) | Prints the pull request's cost box. |
| `issue-claim-release` | PostToolUse (`gh pr merge`) | Removes `in-progress` from every issue the merged pull request closes, once the merge is confirmed. |
| `debt-sentinel-touch` | PostToolUse (`gh` issue and merge commands) | Refreshes the statusline's tech-debt count. |
| `workflow-doctrine-inject` | SessionStart, PostToolUse (EnterWorktree, `git`, `gh pr checkout`) | Injects the execution doctrine when the session works on a branch or in a worktree, and steers a plain `git worktree add` under `.claude/worktrees/` into `EnterWorktree`. |
| `context-checkpoint-inject` | PostToolUse | At the red, fire, and skull context bands, tells the main session to save its place and ask to continue or clear. |
| `context-checkpoint-subagent` | PostToolUse | The same checkpoint for a sub-agent that opted in with a handoff path. |
| `provision-worktree` | SessionStart, PostToolUse (EnterWorktree) | Links shared state into a worktree, gives it its port slot and port file, and installs dependencies and typed routes. |
| `ports-session-start` | SessionStart | Records which session launched which dev server, and stops servers from ended sessions and removed worktrees. |
| `wiki-session-start` | SessionStart | Runs the wiki-landing janitor and lists merged worktrees with their removal commands. |
| `debt-session-reconcile` | SessionStart | Re-checks a shown `/gaia-debt` count against GitHub. |
| `usage-capture` | SessionStart, Stop | Records the session's model usage to the local usage ledger. |

`local-janitor.sh` and `post-audit-status.sh` ship in `.claude/hooks/` without a registration of their own: the session-start hook runs the first, and the merge workflow calls the second to post `GAIA-Audit`.

## Not hooks, but enforced

- **Native git hooks** in `.githooks/`: `pre-commit` (typecheck, lint-staged, tests) and `commit-msg` (commitlint). See [Git hooks and conventions](/workflow/git-conventions/).
- **Permission rules** in `.claude/settings.json`: for example, Claude cannot edit `pnpm-lock.yaml` directly; `pnpm install` regenerates it.
- **The `GAIA-Audit` required check** on GitHub, registered by [`/setup-gaia`](/getting-started/setup-gaia/).

## Your own hooks

If you register hooks of your own, check that they resolve from the repository root:

```bash
bash .gaia/scripts/check-hook-command-rooting.sh .
```

## Retired in 2.0.0

The wiki drift, commit-nudge, session-stop, and auto-commit squash hooks are gone, along with the lockfile, bare-test, vitest-globals, i18n-strings, story-exists, and trailer-stamp hooks: each duplicated a permission rule, a rule, or a skill, or guarded something that cannot happen. `block-env-write` is folded into `block-secrets-write`, and the two read-side secret guards into `block-sensitive-read`. The 2.0.0 migration removes the old files and registrations.
