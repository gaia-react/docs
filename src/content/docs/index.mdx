One command scaffolds the GAIA React framework and automatically launches Claude Code for the rest of setup.

## Prerequisites

- Node 22.22.0 or later. Check with `node --version`.
- Claude Code 2.1.292 or later, reachable as `claude`. Run `claude update` if you are on an older version.
- The GitHub CLI, `gh`, authenticated with `gh auth login`. GAIA's pull request and merge workflow runs on it.

`pnpm` is not required up front. If `pnpm install` runs (the default) and pnpm is missing, `create-gaia` installs it for you. With `--no-install`, it installs nothing. GAIA uses pnpm 12, pinned in `package.json`.

`uv` is required for the Serena MCP server. GAIA will install it for you during setup if you don't already have it.

## New GAIA project

For greenfield projects, run this command in the terminal:

```bash
npx create-gaia@latest my-app
```

`my-app` becomes the project directory. It must be empty or not yet exist; the scaffolder won't write into a non-empty directory.

1. Downloads the latest GAIA release bundle and extracts it
2. Runs `git init` and creates a single `chore: scaffold from GAIA <version>` commit
3. Installs the packages
4. Launches Claude Code in the project directory and runs `/gaia-init` automatically

Follow along with the `/gaia-init` [walkthrough](/getting-started/gaia-init/). Once setup is done, the [Workflow overview](/workflow/) shows how a normal session works, and [What you meet, and when](/getting-started/what-you-meet/) shows what GAIA does as your first commits and pull requests land.

The project is a pnpm workspace: the shared Claude setup at the root, and the React app in `frontend/`. See [Project layout](/getting-started/project-layout/).

### Permissions on the first run

When you scaffold a project, `npx create-gaia` launches Claude Code once with `--dangerously-skip-permissions` and runs `/gaia-init`. That single run rewrites files, registers tools, and wires the project end to end. The flag lets it finish without stopping to ask permission at every step.

That flag applies to the setup run only. Nothing stores it. When `/gaia-init` finishes, it tells you to exit Claude and relaunch, because the new skills and plugins load only in a fresh session. How you relaunch is your call: plain `claude` if you'd rather approve actions as they happen, or `claude --dangerously-skip-permissions` if you don't want to be interrupted.

Either way, GAIA's guardrails stay on. They run as hooks on every tool call, not as permission prompts, so skipping the prompts doesn't disable them. Every scaffolded project ships hooks that block actions like:

- committing or pushing directly to `main`, or force-pushing it
- `rm -rf` on dangerous targets (`/`, `~`, `.git`, `.claude`, `node_modules`, the repo root)
- reading `.env` files, keys, and credentials, or writing secrets into the repo
- committing with `--no-verify` to skip the native pre-commit hook's typecheck, lint, and test floor
- opening a pull request that is not a draft, or whose title is not a Conventional Commit
- merging a pull request the [Code Audit Team](/workflow/code-audit-team/) has not cleared

These hold whether or not you pass the flag. See the [hooks reference](/reference/hooks/) for the full set, and the [gate reference](/reference/gates/) for why each one exists.

## Cloning an existing GAIA project

For existing projects (for example, created by a teammate), after you clone the repo:

1. Run `claude --dangerously-skip-permissions`
2. Run `/setup-gaia` in Claude Code

Follow along with the `/setup-gaia` [walkthrough](/getting-started/setup-gaia/).

<Aside type="note">
You can leave out `--dangerously-skip-permissions`. It adds friction to setup, but the choice is yours.
</Aside>

## Upgrading a 1.x project

A GAIA 1.6.1 project moves to 2.0.0 through a migration Claude runs in your session. See [Upgrading from 1.x](/getting-started/upgrading/).

## Pinning to a specific version

Useful when you want a specific version of GAIA.

```bash
npx create-gaia@latest my-app --version v2.0.0
```

Other flags: `--no-install` skips the dependency install, `--no-git` skips `git init` and the first commit, and `--no-claude` skips launching Claude Code and prints the manual steps instead.
