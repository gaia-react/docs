GAIA ships commands for doing work and commands for keeping the project in shape. This page covers the second kind. You rarely need to remember them: each one surfaces as a statusline nudge when it is due.

## Maintenance commands

| Command | Statusline nudge | What it does |
| --- | --- | --- |
| [`/gaia-fitness`](/maintenance/fitness/) | none | Lints the Claude integration (skills, commands, agents, rules, hooks, settings, `CLAUDE.md` files, wiki) with a fixed rule catalog, grades it F to A+, and heals your own files one at a time on a yes. |
| [`/gaia-cleanse`](/maintenance/cleanse/) | 🔎 | Cleanses memory and auto-loaded files of duplication with the wiki, contradictions with the wiki, stale entries, and over-budget base context. Researches, then asks before it applies. |
| [`/gaia-debt`](/maintenance/debt/) | 🐛 | Fixes the `tech-debt` backlog, highest severity then oldest first, one issue or a related batch per run, through the audit gate. Closes the issues on merge. |
| [`/gaia-codify`](/maintenance/codify/) | 🔨 | Turns a finding the Code Audit Team keeps making into a guard: a deterministic check, a skill, or a path-scoped rule, with your approval. |
| [`/gaia-residue`](/maintenance/residue/) | 🧹 | Triages the trade-offs reviewers accepted at merge: dismiss, keep, or promote each to a tech-debt issue. Never fixes code. |
| [`/gaia-serena-sync`](/maintenance/serena-sync/) | 🔭 | Adds languages your project has grown to Serena's index, on your yes. |
| [`/gaia-wiki`](/maintenance/wiki/) | 🧠 | Runs wiki sync, consolidate, and lint with fixes, as one commit and one pull request. Takes no arguments. |

## Update commands

| Command | Statusline nudge | What it does |
| --- | --- | --- |
| [`/update-deps`](/maintenance/update-deps/) | 📦 | Resolves security advisories, then updates outdated packages by group, through one quality gate. |
| [`/update-gaia`](/maintenance/update-gaia/) | 🚀 | Pulls the latest GAIA release into your project with a three-way merge, verifying the release bundle first. |

## The statusline

GAIA's statusline draws its nudges on the right, each led by its emoji icon: `⚙️ /setup-gaia`, `🚀 /update-gaia`, `🔭 /gaia-serena-sync`, `📦 /update-deps`, `🔎 /gaia-cleanse`, `🔨 /gaia-codify`, `🐛 /gaia-debt`, `🧹 /gaia-residue`, and `🧠 /gaia-wiki`. It also shows when a teammate's GAIA update is in progress. The nudges fit the terminal width: on a narrow terminal they shrink to icons, with a `+N` for those hidden, and refit within 15 seconds of a resize. The debt and residue counts refresh as soon as those commands finish.

Inside a linked worktree the statusline shows only a blocking setup prompt, since the maintenance commands run from the main checkout. The left side shows GAIA's own bar (project, branch, model and effort, and a context bar), or your global statusline if you chose to keep it in [`/setup-gaia`](/getting-started/setup-gaia/#phase-statusline-left-side).

## Which one to run

Pick by symptom:

- The integration feels off, a skill is not triggering, a rule is not loading: [`/gaia-fitness`](/maintenance/fitness/).
- The base context feels heavy, or machine-local memory has grown large: [`/gaia-cleanse`](/maintenance/cleanse/).
- The `tech-debt` backlog has grown: [`/gaia-debt`](/maintenance/debt/).
- The audit keeps flagging the same class of problem: [`/gaia-codify`](/maintenance/codify/).
- Accepted residuals have piled up in merged pull requests: [`/gaia-residue`](/maintenance/residue/).
- The project grew a language Serena is not indexing: [`/gaia-serena-sync`](/maintenance/serena-sync/).
- The wiki trails the code, or wiki pages overlap: [`/gaia-wiki`](/maintenance/wiki/).

The boundary between `/gaia-cleanse` and `/gaia-wiki` is deliberate. `/gaia-cleanse` reconciles memory and auto-loaded files against the wiki. Redundancy and broken links inside the wiki belong to `/gaia-wiki`. Conflicts between two instruction files belong to Claude Code's own `/doctor prompt-audit`.

## How maintenance commands run

Every maintenance command (`/gaia-wiki`, `/gaia-residue`, `/gaia-codify`, `/gaia-fitness`, `/gaia-cleanse`, `/update-deps`, `/update-gaia`) follows the same pattern:

1. **It starts from the main checkout.** Inside a linked worktree it refuses and names the main checkout to run it from.
2. **It offers to pull first** when your checkout's GAIA version lags the remote.
3. **It does its work on a branch of its own**, right before its first write: a worktree cut from the default branch by default, following your team's [isolation policy](/workflow/work-lifecycle/#3-isolate). It never writes onto the branch your checkout holds. The branch is named for the command and a timestamp, for example `deps/2026-10-20-1432`.
4. **It commits, opens a draft pull request, and, on a run started from the main branch, merges it** through the [Code Audit Team](/workflow/code-audit-team/), waiting up to ten minutes for a queued merge. Some ask before merging: `/gaia-residue` asks once, and `/gaia-fitness` and `/gaia-codify` publish only on your answer.
5. **It cleans up** the worktree and branch and pulls the default branch. A worktree holding unresolved work is kept, with the commands to remove it.

A run that ends with nothing to publish removes its empty branch and worktree.

Each run ends with a [cost line](/reference/cost/) showing what it spent.

## GAIA CI is gone

GAIA 1.x could run wiki sync, dependency updates, a security audit, and stale-branch cleanup on GitHub Actions. 2.0.0 removes that: Claude no longer runs on GitHub Actions. The commands above run locally, and the statusline tells you when each one is due. The Tests, Chromatic, and PR Conventions workflows still ship; see [Git hooks and conventions](/workflow/git-conventions/#github-workflows-that-ship).
