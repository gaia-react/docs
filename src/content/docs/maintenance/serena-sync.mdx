`/gaia-serena-sync` finds languages your project now contains that [Serena](https://github.com/oraios/serena) is not indexing, and on your yes adds them to Serena's configuration.

Serena picks a list of languages when it first starts in a project, saves it to `.serena/project.yml`, and never checks again. If the project later adds another language (a Go service beside `frontend/`, a folder of Python scripts), Claude can't use Serena to find functions, classes, and other symbols in that code until the language is added to the list.

It runs from the main checkout only. Only you start it, by typing it; Claude never runs it on its own.

## When to use it

When the statusline shows:

```
🔭 /gaia-serena-sync (missing: go)
```

The nudge is worked out in the background every 6 hours, so it can be a little behind your files. The command checks again when you run it.

## What it does

1. **Checks Serena is active.** When Serena is not a registered MCP server, or `.serena/project.yml` does not exist, it says so and stops. It changes nothing for a project that does not use Serena.
2. **Checks again which languages are missing.** When every language is already indexed, it says Serena is in sync and stops.
3. **Names the missing languages** and prints the manual edit, for example: add `go` to the `language_servers:` list in `.serena/project.yml` (`languages:` on a file from before Serena 1.7). That instruction is always shown, so you can always make the change by hand.
4. **Asks once** for the whole set: **Apply** (recommended) or **Skip**. Nothing is written before you answer.
5. **On Apply**, appends every missing language to the list, keeps every existing entry and every other field as it was, and clears the statusline nudge. Then **restart Serena** (or your Claude session): Serena reads the file only at startup.

When the file is written in a way GAIA can't safely edit (YAML anchors, no list to add to, or both `language_servers:` and `languages:` present), it explains why and leaves you the instruction to do it by hand. It never runs `serena project create`, which can regenerate the file and overwrite `.serena/project.local.yml`.

## Serena in a GAIA project

`/gaia-init` and `/setup-gaia` register Serena v1.7.0 for your user. GAIA's `code-search` rule sends questions about code symbols (where is X defined, what calls Y) to Serena, and questions about decisions and their reasons to the wiki. The `serena-cc-override` rule nudges Claude toward Serena's symbol tools at session start. For the strongest effect, start sessions with Serena's system-prompt override; see [`/gaia-init`](/getting-started/gaia-init/#5-claude-tooling).
