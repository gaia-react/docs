`/gaia-cleanse` reviews what Claude remembers and what it loads at every session start (machine-local memory, `CLAUDE.md` files, and rules) against the wiki, the project's source of truth. It finds entries that duplicate the wiki, contradict it, reference things that no longer exist, or push the auto-loaded context over budget, then asks one question before changing anything.

It runs like every [maintenance command](/maintenance/#how-maintenance-commands-run): from the main checkout, in a worktree of its own, ending in a pull request.

In 1.x this command was `/gaia-audit`. There is no alias.

## When to use it

Run it after a stretch of work, or when your base context feels heavy. The statusline nudges you with `🔎 /gaia-cleanse (<reason>)`, showing the highest-priority reason only:

- `resume draft`: a report is waiting to be applied.
- `<N> new memories`: machine-local memory has grown by 10 or more entries since the last applied cleanse.
- `<N> days since review`: 30 or more days since the last applied cleanse.
- `over budget`: an auto-loaded file is over its budget (an oversized `CLAUDE.md`, nested `CLAUDE.md`, or rule).

## How to invoke

```
/gaia-cleanse
```

Research, review at the gate, then apply on your yes.

```
/gaia-cleanse "memory only"
```

A scope hint narrows which stores or files the research looks at. It can only narrow: it never changes the report format, the action types, the guardrails, or a specific edit.

```
/gaia-cleanse --apply
```

Re-run the apply stage against the most recent report, to resume an interrupted run or retry after fixing what made actions skip.

## What it looks at

| Store | Path | Auto-loaded? |
| --- | --- | --- |
| Machine-local project memory | `~/.claude/projects/<project>/memory/` | `MEMORY.md` (first 200 lines); entries on demand |
| Machine-local agent memory | `~/.claude/agent-memory/` | Per agent, on demand. Reported, never edited: it is shared by every project on the machine. |
| Project agent memory | `.claude/agent-memory/` | Per agent, on demand |
| Root `CLAUDE.md` | `CLAUDE.md` | Every session |
| Nested `CLAUDE.md` files | `**/CLAUDE.md` (for example `frontend/CLAUDE.md`) | When the working directory matches |
| Project rules | `.claude/rules/*.md` | At session start, or on a `paths:` match |
| Wiki | `wiki/` | On demand. The reference the others are checked against. |

Each entry is classified:

- **DUPLICATE**: the fact is already canonical in the wiki, so the local copy is removed.
- **PROMOTE**: durable knowledge that lives only in memory moves to a named wiki page.
- **KEEP-LOCAL**: genuinely machine-local (a personal preference, a machine path); left alone.
- **STALE**: references a file, branch, or feature that no longer exists.
- **CONFLICT**: a memory entry that contradicts the wiki is resolved toward the wiki.

Store counts, budgets, and dead-path signals come from GAIA's own CLI (`gaia fitness inventory` and `gaia fitness check`); the model judges only what a script cannot.

### What it does not touch

- **Conflicts between instruction files.** Two `CLAUDE.md` files, rules, skills, commands, or agents that disagree with each other are not judged here; run `/doctor prompt-audit` for those. An instruction file that contradicts the wiki is reported and filed as a `tech-debt` issue, never edited.
- **Files you do not own.** It edits only your project's own files and memory, and asks you per file. A finding in a GAIA-shipped file is reported for [`/update-gaia`](/maintenance/update-gaia/) to fix; a third-party file goes to its vendor; machine-wide agent memory is yours to edit by hand.
- **The wiki's own redundancy and broken links.** Those belong to [`/gaia-wiki`](/maintenance/wiki/).
- **Rules from `/gaia-codify`.** A rule carrying a `gaia-harden:` provenance marker is treated like any other rule, except it is never pruned just because its pattern stopped recurring. A quiet pattern is the rule working.

## The flow

1. **Research.** A Sonnet sub-agent writes a report to `.gaia/local/cleanse/KNOWLEDGE-<timestamp>.md` (gitignored) with every proposed action spelled out exactly: paths, the current content it expects, and the replacement.
2. **Verification round** (recommended, optional). When the report has at least one action, three parallel checks test each action's claim against the real stores, the wiki, and the repository, and drop or correct a mis-classified one. Memory edits have no git undo, so this catches a wrong delete before you approve it.
3. **One decision gate**, in your session:
   - **Apply**: asks which of your own files it may edit, then applies the report on its own branch, files any out-of-scope problem as a `tech-debt` issue, commits, opens a pull request, and merges it.
   - **Discuss / refine**: talk it through; the report is edited in place and the gate asked again.
   - **Decline**: delete the report. Nothing is applied, filed, or published.

A clean run (zero actions) skips the round and the gate and applies itself, once a recount confirms it covered every store.

<Aside type="tip" title="Safe by default">
Running `/gaia-cleanse` researches and reports. Nothing in memory, rules, or the wiki changes until you choose Apply.
</Aside>

## Action types

| Action | What it does |
| --- | --- |
| `delete` | Removes a memory or rules file whose facts are canonical in the wiki, only if the file still matches what the report saw. |
| `delete-entry` | Removes one block, such as a heading section in `MEMORY.md`, by exact match. |
| `promote` | Moves durable knowledge from memory to a named wiki page, then removes or trims the source. |
| `shrink` | Replaces inline content in an auto-loaded file with a wikilink. The current block must match exactly. |

Every action carries a drift signal. When a file changed since the report, that action is skipped and noted, never forced. A file with uncommitted changes is skipped before anything runs.

## Reports and resume

A report is `draft` until applied, then `applied` or `applied-partial` (some actions skipped, so `--apply` retries the rest). Drafts are never pruned. Finalized reports keep the newest five and delete anything beyond that older than 30 days.

`--apply` checks the report's age: up to 24 hours proceeds, 24 to 72 hours proceeds with a warning, and over 72 hours stops and asks for a fresh run.

Memory edits live outside the repository under `~/.claude/` and are never committed. A run that only changed memory opens no pull request.

The run ends with a [cost line](/reference/cost/).
