`/update-deps` keeps your dependencies current and your security advisories resolved, in place of Dependabot's version and security pull requests. Advisories come first, each fixed the least invasive way. Then outdated packages, previewed by group so you can snooze what you are not ready for. Everything passes one quality gate, in its own worktree, and lands as one `chore(deps)` pull request that merges once checks are green.

It runs like every [maintenance command](/maintenance/#how-maintenance-commands-run): from the main checkout, in a worktree of its own cut from the default branch, whichever branch your checkout holds. Run by [`/gaia-init`](/getting-started/gaia-init/), it asks nothing and leaves its changes for the init commit instead.

## When to use it

The statusline shows `📦 /update-deps (N outdated, M security)` when packages are outdated or advisories are open. It counts both Dependabot alerts and `pnpm audit` advisories, and leaves out groups you snoozed. Click it, or ask "update dependencies", "bump deps", or "fix Dependabot alerts".

## How to invoke

```
/update-deps
```

The full interactive run: preview, decide, apply.

```
/update-deps --security
```

Only the security advisories, plus the major bumps they need. Every other outdated package is left alone.

```
/update-deps --scope react-router
```

One companion group, with no preview. The security phase only reports here.

`--security` and `--scope` cannot be combined.

## Security advisories first

`/update-deps` reads open advisories from `pnpm audit` and from Dependabot alerts when it can read them. Dependabot alerts are read as data only: advisory text is never pasted into a command, file, question, or comment.

Advisories appear first in the preview, ranked, each with its proposed resolution. The resolutions, least invasive first:

1. **In-range refresh**: the fixed version is already inside your allowed range, so a lockfile refresh picks it up.
2. **Chain-head bump**: the package at the head of the dependency chain moves to a version that pulls in the fix. A major chain-head bump is asked first and runs with its migration.
3. **Security-floor override**: an `overrides:` entry in `pnpm-workspace.yaml` forces a patched version of the vulnerable sub-dependency.
4. **Alert dismissal**: when no fix exists, or you decide to live with it, Claude asks once per advisory whether to dismiss the Dependabot alert, naming every alert, the reason (`tolerable_risk` or `not_used`), and the comment it will post. Nothing is dismissed without your yes.

A resolution that fails the quality gate is reverted, and the advisory is reported still open with the reason.

## Preview and decision

Updates are grouped into **Security**, **Major**, **Non-semver**, **Minor**, and **Patch**. A companion group shows as one block and updates as one unit. The groups include react-router, react, tailwindcss, shadcn, storybook, vitest, playwright, i18next, msw, vite, zod-conform, stylelint, prettier, and eslint. Packages outside a group update on their own, and `typescript` is deliberately its own group.

You choose:

- **Update all** (or **Update the rest** when you have snoozed groups)
- **Choose what to skip**: name packages or groups to snooze, an advisory key to decline, or `sub-dependencies` to skip that part this run
- **Update everything incl. snoozed**, when snoozes exist
- **Cancel**: no branch, no changes

A snooze is local to your machine (`.gaia/local/declined-updates.json`) and lapses when a newer version ships or after 14 days.

## What runs

1. **Override audit.** Every `overrides:` entry is tested: it is removed only when removing it causes no peer-dependency error **and** no new advisory, so a security floor is never dropped by accident.
2. **Minor and patch updates** (Wave A).
3. **Major updates**, one group at a time (Wave B), each with its migration. If the gate fails after one remediation pass, that group is reverted and reported as skipped.
4. **Sub-dependencies** refresh to the newest versions their parents allow, skipping releases too new to trust. Reverted as a whole if the gate fails.
5. **Security resolutions**, then the override audit again.
6. **Quality gate**: `pnpm typecheck`, `pnpm lint`, `pnpm test --run`, `pnpm pw`, and `pnpm build`.
7. **Publish**: one commit, `chore(deps): ...` (`chore(deps-dev):` when only devDependencies moved), a draft pull request, merged once checks are green, then local cleanup.

A pull request that changes only dependency manifests clears the audit gate through its `chore(deps)` bypass; one that also carries a migration edit gets the full [Code Audit Team](/workflow/code-audit-team/) audit.

It also reports when the global `playwright-cli` binary is behind.

## Release-age window

pnpm refuses to install a release younger than 3 days (`minimumReleaseAge` in `pnpm-workspace.yaml`), and the setting is strict. **Why:** a compromised package version is usually caught and pulled within days, so waiting keeps a poisoned release out of your lockfile. See the [gate reference](/reference/gates/#release-age-window).

## Version holds

To cap a package below its latest release, add a `gaia.updateDepsHold` map to the root `package.json`. It maps a package name to a version-prefix ceiling:

```json
{
  "gaia": {
    "updateDepsHold": {
      "vite": "8.0"
    }
  }
}
```

- `"8.0"` holds the package at the highest published `8.0.x`.
- `"8.0.16"` freezes it at exactly that version.
- `"8"` holds it at the highest `8.x`.

A hold is committed and never lapses until you remove it. A hold caps only the package it names; hold a coupled sibling too when its peer range demands more. Held packages are listed above the preview:

```
Held by config (not offered): vite (current 8.0.16, ceiling 8.0)
```

## Where dependencies live

The project is a pnpm workspace with one lockfile at the root. App dependencies are in `frontend/package.json` (add one with `pnpm -C frontend add <pkg>`); harness dependencies and `gaia.updateDepsHold` are in the root `package.json`. `overrides:` and `minimumReleaseAge` are in the root `pnpm-workspace.yaml`.

After any change to `msw`, `pnpm -C frontend msw:init` regenerates `frontend/public/mockServiceWorker.js`; a test fails when it drifts from the installed msw.

<Aside type="note">
[`/setup-gaia`](/getting-started/setup-gaia/) leaves Dependabot alerts on and turns Dependabot's own security pull requests off, so `/update-deps` is the one source of dependency pull requests. If your repository has a Dependabot npm entry or a Renovate config, remove the overlap, or both open duplicate pull requests.
</Aside>
