Skills that govern code generation and review. Each one loads automatically when its trigger phrasing matches the conversation. You don't invoke them by name.

The React app's skills live in `frontend/.claude/skills/` and load in sessions that work on the app. `tdd` and `naming-conventions` live in the root `.claude/skills/` and apply anywhere in the repository.

## TypeScript

Patterns and conventions for TypeScript: `type` over `interface`, explicit return types on exported functions, no enums (`as const` objects with derived types instead), no `switch`, at most three positional parameters, `undefined` over `null` for absence you control, and Zod 4's `z.literal([...])` over `z.enum()`.

**One source of truth.** Before defining a constant list, union type, schema, or lookup map, search for an existing one and import it. Every other shape of the set is derived from the one source, and maps keyed by a union use `satisfies Record<Union, ...>`, so adding a member is a type error everywhere it is not handled.

**Triggers** when writing or reviewing TypeScript: typing exports, choosing between `type` and `interface`, defining Zod schemas, defining a shared constant list or union, structuring function parameters, or avoiding switch statements and enums.

**Example phrasing:** "type this Zod schema", "should this be a type or an interface", "add a status to this union".

Source: `frontend/.claude/skills/typescript/SKILL.md`.

## React Code

Conventions for React components, pages, routes, hooks, and forms, applied through four checks before Claude writes code:

- **Hook check** for `useEffect`, `useCallback`, and `useState` misuse.
- **Form element check.** Native `<input>`, `<select>`, `<textarea>`, checkboxes, and buttons become the shadcn/ui controls in `~/components/ui/` (`Input`, `NativeSelect`, `Textarea`, `Checkbox`, `RadioGroup`, `Button`), composed into `Field` parts and wired with Conform. `@conform-to/zod` is always imported from its `/v4` subpath; the bare import is a runtime error lint flags.
- **Translation check**: every user-visible string comes from `t()`.
- **React 19 idiom check**: `ref` as an ordinary prop (no `forwardRef`), `use()` over `useContext`, `<Context>` over `<Context.Provider>`, guarding the `&&` numeric-0 leak, and React Router's form handling instead of `useActionState`, `useFormStatus`, or `useOptimistic`.

**Memoization is compiler-first.** React Compiler is on by default, so plain code needs no `useMemo`, `useCallback`, or `memo`. A manual memo is allowed only where a value crosses into code the compiler does not compile, or where a component bails out of compilation and the memo is measured to matter, and each one carries a comment naming its case.

**Data loading** follows one route data layer: URL-owned data through a server `loader` by default (or a `clientLoader`), component-owned data through TanStack Query when it is enabled.

Before adding a dependency or hand-rolling a primitive, the skill walks a platform-first ladder: existing project code, then browser-native APIs (`Intl`, `URL`, `crypto.randomUUID()`, `structuredClone()`, modern CSS), then an installed dependency, then a new one, then custom code. It also covers component extraction and the route/page split (`app/routes/` thin shells, `app/pages/` for UI).

**Triggers** when writing or reviewing React components, hooks, or event handlers, deciding on component extraction, deciding whether a manual memo or `"use no memo"` is justified, debugging stale closures or infinite re-renders, weighing a new dependency, or choosing a React 19 idiom.

**Example phrasing:** "this useEffect is firing twice", "extract this section into its own component", "wire up a Conform form for sign-up".

Source: `frontend/.claude/skills/react-code/SKILL.md`.

## Styling

### Tailwind

Every color is a shadcn role token (`bg-background`, `text-foreground`, `text-muted-foreground`, `bg-primary`, `border-input`, `text-destructive`), never a raw palette class or an arbitrary color, so one token carries both light and dark themes. `@gaia-react/lint` fails raw palette classes and arbitrary values.

`cn` (from the `cn` package) is the only class utility. It joins classes and resolves conflicts, so a caller's `className`, passed last, overrides a component default. A conditional class is `cond && 'class'`; lint rejects object conditionals and empty-branch ternaries. Multi-class variants use `cva`. Custom values use `rem`, never `px`, and a new role token is named for what the element is.

**Triggers** when writing Tailwind classes, combining classes with `cn`, writing conditional classes, building variants, defining `@theme` tokens, picking `rem` or `px`, or working with breakpoints.

**Example phrasing:** "this needs a hover variant", "name this color token", "let the caller override the padding".

Source: `frontend/.claude/skills/tailwind/SKILL.md`.

### Skeleton Loaders

Skeleton loading states that are pixel-perfect matches of the real content. Uses real HTML elements with the same font classes plus a shared `shimmer` class; non-text elements stay as empty `<div>`s. Includes the 200ms delay pattern that suppresses a flash on fast loads.

Static translatable text in a skeleton uses `t()` or `<Trans>`, the same call the real component uses, so widths match. The skeleton root carries `aria-hidden`, and the region receiving the content carries `aria-busy="true"` or a visually hidden `role="status"` live region.

**Triggers** when adding loading states, building skeletons for async data, handling pending route transitions, or preventing layout shift.

Source: `frontend/.claude/skills/skeleton-loaders/SKILL.md`.

## Test Driven Development

Based on Matt Pocock's [TDD Skill](https://www.aihero.dev/skill-test-driven-development-claude-code), tailored for GAIA. A vertical-slice red-green-refactor loop: one failing test, the code that passes it, then the next. Tests verify behavior through public interfaces. `tdd` runs the loop; its React companion, `tdd-react`, holds the frontend testing reference.

**Stories are the component tests.** A component is tested by its Storybook story with a play function, run in real Chromium. React Testing Library, happy-dom, and jsdom are gone. Hook tests use `vitest-browser-react`. HTTP is mocked with MSW. Every story is checked for accessibility by `addon-a11y`, and a story that weakens its accessibility check fails the tests unless it opts out with a stated reason.

**The RED gate.** On the deterministic surface (pure utilities, service parsers, hooks), a commit hook refuses a new test that was never seen to fail first. Stories and Playwright tests are exempt, since their environment cannot guarantee a clean failing run. For those, the `worthiness-evaluator` agent judges each new test for honesty and worthiness and returns keep, fix, or delete; fixes apply as ordinary edits, and deletes need your confirmation. A merge hook checks that every changed test of that kind was judged.

**Triggers** when building features or fixing bugs with TDD, mentioning "red-green-refactor", asking for integration tests, or asking for test-first development.

**Example phrasing:** "let's TDD this", "write a red test for the login flow".

Source: `.claude/skills/tdd/SKILL.md`, `frontend/.claude/skills/tdd-react/SKILL.md`.

## Playwright CLI

Microsoft's [Playwright CLI](https://github.com/microsoft/playwright-cli) skill for browser automation, vendored byte-for-byte from upstream. Navigate, click, type, screenshot, manage cookies and storage, run parallel sessions, and read element refs from generated snapshot files. It shells out to the global `playwright-cli` binary, which `/update-deps` reports when it falls behind.

**Triggers** when navigating websites, filling forms, taking screenshots, testing web applications, or extracting information from pages. You can also say "use playwright for ...".

Source: `frontend/.claude/skills/playwright-cli/SKILL.md`.

## ESLint Fixes

Claude usually does the right thing with ESLint errors. This skill handles known cases where it resolved specific errors badly, and autofix conflicts where one rule fights another. If you see Claude resolving an error in an undesirable way (disabling the rule instead of fixing the cause), ask it to improve the `eslint-fixes` skill for that error. Every `eslint-disable` needs a `-- reason`.

Source: `frontend/.claude/skills/eslint-fixes/SKILL.md`.

## Accessibility Fixes

Fixes specific axe-core violations: `color-contrast`, `label`, `image-alt`, `button-name`, `link-name`, `region`, `heading-order`, the `aria-*` rules, `tabindex`, `duplicate-id`, and others, with a fix-then-verify loop for anything not listed. Fixes reach for role tokens and the `ui` controls, so they hold in both themes. General guidance lives in the `accessibility` rule; this skill handles the concrete fix once a violation is reported.

**Triggers** when an axe rule id appears in output from a story under Vitest (`addon-a11y`), the Playwright helper (`frontend/.playwright/a11y.ts`), or `code-audit-frontend`'s accessibility findings.

Source: `frontend/.claude/skills/a11y-fixes/SKILL.md`.
