These skills create new files in the React app that follow the project's conventions. They run GAIA's bundled `gaia scaffold` command for you, so you don't need to remember its flags: describe what you want, and the skill asks for anything missing. Each one runs the command from the repository root (`./.gaia/cli/gaia scaffold ...`) and writes into the `frontend/` package. Paths below are relative to `frontend/`.

Files and folders under `app/components`, `app/pages`, and `app/hooks` are kebab-case (lowercase words joined by hyphens, like `price-card`), and `@gaia-react/lint` enforces it.

## New Component

It first checks whether [shadcn/ui](https://ui.shadcn.com/) already offers the component (a dialog, tabs, a popover). If it does, it runs `pnpm shadcn add <name>`, which copies the component's source into your project as a single file, `app/components/ui/<name>.tsx`; GAIA never edits those files. Otherwise it creates a component folder: `app/components/<name>/index.tsx` and `tests/index.stories.tsx`, a story whose play function is the component's test. There is no separate test file.

**Confirms:** name (kebab-case or PascalCase; the folder uses the kebab-case form), parent folder (default `app/components/`), and props.

**Triggers** when you ask to create a component, scaffold a card, make a button, or add a new component.

**Example phrasing:** "create a price-card component", "scaffold a user-avatar with a name and url prop".

Underlying CLI: `gaia scaffold component <name> [--parent <dir>] [--props "a:string,b:number"] [--json]`. `--props` takes comma-separated `name:type` pairs, and types that contain commas (`Record<string, unknown>`, tuples, function types) work too. `app/components/ui` is refused as a parent.

Source: `frontend/.claude/skills/new-component/SKILL.md`.

## New Hook

Creates a custom React hook, `app/hooks/use-<name>.ts` (named export `useName`), with a `vitest-browser-react` test at `app/hooks/tests/use-<name>.test.ts`.

**Confirms:** name (`use-kebab` or `useCamel`), parameters, and return type.

**Triggers** when you ask to create a hook, make a `useFoo` hook, or describe state or effect logic you want to reuse.

**Example phrasing:** "make a useCountdown hook", "extract this into a useFormSubmission hook".

Underlying CLI: `gaia scaffold hook <useFoo> [--params "a:string,b:number"] [--returns "ReturnType"] [--json]`.

Source: `frontend/.claude/skills/new-hook/SKILL.md`.

## New Route

Creates a route file, `app/routes/<group>.<name>.tsx` (named with the flat file convention of `@react-router/fs-routes`), and its page, `app/pages/<name>/page.tsx`, with `tests/page.stories.tsx`. The story is the page's test. The route file stays small (`loader`, `action`, `meta`, and a one-line default export); the UI lives in the page.

When you connect it to a service, it writes everything from loading the data to showing it on the page, in one of three ways:

| `--data` | What it writes |
|---|---|
| `server` | a server `loader` the page reads with `useLoaderData` |
| `client` | a `clientLoader` and a `HydrateFallback` |
| `query` | a `clientLoader` that loads the data into the [TanStack Query](https://tanstack.com/query/latest) cache, and a page that reads it with `useSuspenseQuery` (needs Query installed) |

`--shape list` writes `<group>.<name>.tsx`; `--shape detail` writes `<group>.<name>_.$id.tsx`. The page story gets its data from [MSW](https://mswjs.io/) mocks.

**Confirms:** name (kebab-case), group (`_public` or `_session`), and the data, action, and i18n options.

**Triggers** when you ask to create a route, add a page, scaffold a path like `/dashboard`, or wire up a route under `_public` or `_session`.

**Example phrasing:** "add a /pricing page in _public", "scaffold a projects list page in _session backed by the projects service".

Underlying CLI: `gaia scaffold route <name> --group <_public|_session> [--data <server|client|query> --service <name> --shape <list|detail>] [--layer <folder>] [--loader] [--action] [--i18n] [--dry-run] [--json]`.

`--dry-run` prints the files it would write without writing them. `--loader` (a loader for the page title and meta tags) cannot be combined with `--data`. With `--action` and `--data`, it writes a create action (list) or an update action (detail), validated by the service's input schema. With `--i18n`, it adds the locale file to the locale barrel (the index file that re-exports the locale files); if the barrel is missing, the command stops with an error that says how to fix it.

Source: `frontend/.claude/skills/new-route/SKILL.md`.

## New Service

Creates an API service in your API's folder under `app/services/` (shipped as `gaia/`, often renamed to the company or API name). It writes request functions built on [Ky](https://github.com/sindresorhus/ky) that check responses against [Zod](https://zod.dev/) schemas, plus the schemas, URL constants, and types, and optionally MSW mock handlers under `test/mocks/<name>/`. When `@tanstack/react-query` is installed and the service has a `get`, it also writes `queries.ts` with query keys and `queryOptions` factories.

**Confirms:** name (kebab-case), endpoints (any of `get`, `post`, `put`, `delete`), the schema as `name:type` pairs, and whether to include mocks.

**Triggers** when you ask to add a service, create the API for a resource, or wire up CRUD (create, read, update, delete) for a resource.

**Example phrasing:** "add a projects service with get and post", "wire up CRUD for tasks with mocks".

Underlying CLI: `gaia scaffold service <name> --endpoints "get,post,put,delete" --schema "id:string,name:string,status:enum(active,archived)" [--layer <folder>] [--mocks] [--json]`. Schema types are `string`, `number`, `boolean`, `datetime`, and `enum(a,b,...)`; add `?` to make a field optional. `--queries-only` adds `queries.ts` to an existing service.

The skill does not connect the service to a page or hook, so you decide where it belongs. [New Route](#new-route) with `--data` does that connection for a route.

Source: `frontend/.claude/skills/new-service/SKILL.md`.
