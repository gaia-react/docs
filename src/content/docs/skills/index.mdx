A skill is a directory with a `SKILL.md` and sometimes supporting `references/` files that load on demand. GAIA ships skills in two places:

- **`.claude/skills/`** at the project root: skills that apply anywhere in the repository.
- **`frontend/.claude/skills/`**: the React app's skills, which load in sessions working on the app.

React Doctor installs per machine as `frontend/.claude/skills/react-doctor`, gitignored. GAIA's workflow commands (`/gaia-spec`, `/gaia-plan`, and the rest) read their instructions from `.claude/skills/gaia/references/`, which has no slash entry of its own.

## How triggering works

Each `SKILL.md` has a `description:` field listing the phrasings and situations that load it. A skill activates when the description matches what you said, not on every prompt. Saying "scaffold a card called price-card" loads `new-component`; saying "this useEffect fires twice" loads `react-code`.

`/gaia-wiki`, `/update-deps`, and `/update-gaia` are skills, so plain-English asks trigger them too. They also surface on the statusline (`🧠`, `📦`, `🚀`) when there is pending work.

User-only commands (`/gaia-init`, `/setup-gaia`, `/gaia-fitness`, `/gaia-forensics`, `/gaia-codify`, `/gaia-residue`, `/gaia-serena-sync`) set `disable-model-invocation`, so Claude never starts them on its own and they do not appear in its skill listing. Type them as slash commands.

## Questions are menus

Every GAIA skill and command asks a choice as a menu (`AskUserQuestion`) with the recommended option first, and prints any prompt or command meant for pasting in a fenced code block. The shipped `user-questions` rule applies the same standard to skills you write.

## Adding your own

Add a directory under `.claude/skills/<name>/` (or `frontend/.claude/skills/<name>/` for an app-only skill) with a `SKILL.md` whose frontmatter sets `name` and `description`, and optionally `model:` to pin a model tier. Claude picks it up in the next session. [`/gaia-fitness`](/maintenance/fitness/) lints it.
