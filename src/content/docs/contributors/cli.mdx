The `gaia` binary is the bundled CLI at `.gaia/cli/gaia`, shipped in every project. Projects rarely run it directly; skills, hooks, and slash commands run it for them. Every subcommand prints a help block on `--help`, and `gaia --help` lists them all.

If you work on the CLI, this page maps its subcommands. The source lives under `.gaia/cli/src/`, which the release bundle leaves out.

## Build layout

`.gaia/cli` is a package in the root pnpm workspace. At release, the scrub removes it from the shipped `pnpm-workspace.yaml` and `pnpm-lock.yaml`, and every CLI source file is left out of the bundle. `pnpm -C .gaia/cli bundle` builds two binaries:

- `.gaia/cli/gaia`: the shipped binary. Entry point `src/index.ts`.
- `.gaia/cli/gaia-maintainer`: the maintainer binary, carrying `labels docs` and the release namespace. Entry point `src/index.maintainer.ts`. Excluded from the bundle.

`src/index.ts` imports no maintainer-only code, so esbuild (the bundler) leaves that code out of the shipped binary. The committed binaries must match a fresh build from source. Any change under `.gaia/cli/src` means rebuilding and committing them (the pre-commit hook does this on the GAIA repo), and CI checks it.

## Top-level subcommands

Source for each lives in its folder under `.gaia/cli/src/`.

### `gaia init`

Per-step handlers for [`/gaia-init`](/getting-started/gaia-init/). Each records its state in `.gaia/init-state.json` so the command can resume.

```
gaia init strip-branding --title <T>
gaia init configure-i18n --locales <list> --strip <bool>
gaia init configure-data-layer [--casing <camel|snake>] [--query <bool>] [--layer <folder>]
gaia init rename --title <T> --kebab <K>
gaia init wire-statusline --mode <global|project|skip>
gaia init bootstrap-env
gaia init write-project-config --sandbox-recommended <bool> [--isolation-policy <policy>]
gaia init finalize
gaia init resume [--from-step <N>]
```

`configure-data-layer` prints one JSON line naming the files it changed and the commands to run next, and can be re-run after init (for example `--query true` to add TanStack Query later). `init` refuses to run outside a scaffolded project root, and in the GAIA source itself.

### `gaia scaffold`

The engine behind the [scaffolder skills](/skills/scaffolders/): `component`, `hook`, `route` (`--data <server|client|query> --service <name> --shape <list|detail>`, groups `_public` and `_session`, `--dry-run`), and `service` (`--layer`, `--mocks`, `--queries-only`).

### `gaia setup`

The steps behind [`/setup-gaia`](/getting-started/setup-gaia/).

```
gaia setup status|mark-step|finalize [--force]|bootstrap-env
gaia setup detect-remote|check-admin|warn-existing-tools
gaia setup enable-delete-branch|configure-dependabot-alerts
gaia setup write-isolation-policy <always-worktree|prefer-worktree|prefer-branch>
gaia setup write-sandbox-recommendation <true|false>
gaia setup record <id> <applied|declined|not-applicable>
gaia setup drift [--features <path>]
```

`drift` lists setup features from `.gaia/setup-features.json` with no recorded decision; `/setup-gaia` and `/update-gaia` act on it.

### `gaia sandbox`

`detect`, `apply`, `record`, and `status` for the decision on whether Bash runs inside the operating system's sandbox. Exits 2 on invalid arguments.

### `gaia labels`

`gaia labels sync` brings a repository's labels in line with `.gaia/labels.json`. See [Labels](/reference/labels/).

### `gaia packages`

`gaia packages sync-settings [--check]` generates `<package>/.claude/settings.json` from the root settings and the package's overlay. The pre-commit hook checks it.

### `gaia update`

The merge steps behind [`/update-gaia`](/maintenance/update-gaia/): `merge-package`, `merge-workspace`, and `merge-audit-ci` (each merges its file field by field and reports what it applied and what conflicted), `merge-region` and `regen-regions` (for generated regions of a file), and `lockfile-command`.

### `gaia update-deps`

The steps behind [`/update-deps`](/maintenance/update-deps/): `run` (finds what is outdated and sorts it into update waves), `decline` (snoozes an update), `global-tools`, `advisories`, `advisory-landed`, `dismiss-alert`, `write-security-cache`, and `check-security-override`.

### `gaia fitness`

The [`/gaia-fitness`](/maintenance/fitness/) linter: `check` (the rule catalog and grade), `rules`, `inventory` (also used by `/gaia-cleanse`), `builtins`, `apply` (the only subcommand that writes a fix, and only to a file you own that has not changed since the check), and `render-card`.

### `gaia codify-tally`, `gaia codify-ledger`

For [`/gaia-codify`](/maintenance/codify/): `codify-tally` counts how often each finding recurs, and `codify-ledger` records the ones you declined.

### `gaia residue-tally`, `gaia residue-cursor`, `gaia residue-record`

For [`/gaia-residue`](/maintenance/residue/): `residue-tally` counts the residuals to triage, `residue-cursor` remembers where a run stopped so the next one resumes there, and `residue-record` records dismissals. `GAIA_RESIDUE_CAP` sets one batch's size.

### `gaia react-perf`

`gaia react-perf reduce <raw.json> [--frame-budget-ms <n>]` condenses a raw render recording into a summary for [`/gaia-react-perf`](/skills/react-performance/).

### `gaia wiki`

The steps behind [`/gaia-wiki`](/maintenance/wiki/): `state`, `commit-classify`, `state-init`, `state-bump`, `log-prepend`, `page-index`, `orphans`, `near-collisions`, `dead-paths`, `frontmatter`, `empty-sections`, `broken-links`, and `chain <begin|commit|finish|refresh-nudge>`, which runs the whole `/gaia-wiki` chain on one branch with one pull request. `chain begin` refuses `main` and `master`; `begin` and `finish` no longer accept `--branch-aware`. `sync land` is removed.

### `gaia ping`

The fire-and-forget usage ping sent by `/gaia-init`, `/setup-gaia`, and `/update-gaia`. `GAIA_TELEMETRY_PING_DISABLE=1` suppresses it.

## Where to find tests

Test files sit beside their source under `.gaia/cli/src/`, run by Vitest:

```bash
pnpm -C .gaia/cli typecheck
pnpm -C .gaia/cli test --run
```

Fixtures live under `.gaia/cli/test-fixtures/`. GAIA's shell layer is tested by bats suites under `.gaia/scripts/tests/` and `.gaia/tests/`; see [CI workflows](/contributors/ci/).

## Surfaces excluded from this reference

Some namespaces are deliberately undocumented in public contributor docs and are not listed above. They remain visible in the source itself.
